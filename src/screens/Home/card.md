## Quirks

Filled by the implementer (S1 draft, lead to check).

1. **Roles.** html has four blocks: Customer (header 4-17, content 20-127), Plumber (header 131-165 shared, content 167-327), Sales_Boy/Dealer (header shared, content 330-514). **Retailer and Sales_Executive have no block**: a Retailer's Home is an EMPTY page (no header, no content). Sales_Executive never shows Home (tab root is SalesExecHome). The constructor/ionViewWillEnter still run for a Retailer: loginBannersApp, product_catalogue_count, karigarHome (with the "Please wait..." loader over the blank page) and offerList.
2. **No module file / own i18n.** home has no .module.ts (tabs.ts imports HomePage). It uses the app-wide TranslateService, never calls use(): the global language (same as RN's global i18n). en.json maps 'Last 7 Days' to 'LAST 7 DAYS'.
3. **Call order.** Constructor: initPushNotification, loginBannersApp, product_catalogue_count. ionViewWillEnter (every time Home becomes active again, e.g. after popping a pushed page): karigarHome (loader) then offerList. RN: mount + navigation 'focus' after a 'blur'.
4. **Loader.** getData() shows "Please wait..." (dismissOnPageChange) and dismisses it on success AND on error (home.ts:209, :217). The other four calls have no loader and no error callback (silent).
5. **Malformed karigarHome.** `r['karigar'].total_balance` throws when karigar is null: the rest of the callback is skipped and every handler that reads karigar_detail then throws (console only). RN: handlers are wrapped in safe() (a throwing onPress would be fatal) so they do nothing, as in Ionic.
6. **Null lists.** `banner.length` / `offer_list.length` on a null from the server throws in Ionic's template; RN shows the empty branch.
7. **Verified checks** use `!= 'Verified'` (scan alerts, Add Plumber, Add Service/Installation Request); Start Checkin only blocks `== 'Pending'`. A missing karigar_detail.status ({} before karigarHome answers) counts as not verified. Alert text "You are account  not verified" has two spaces. Title 'Alert!', cssClass 'action-close', button 'OK'.
8. **Request-exists alerts**: service_exist / installation_exist compared with `== true` ('You have already add service request' / '...installation request'). complaint_exist and open_complaint are stored, never read by a live control.
9. **QR flows.** Plumber: header qr-scanner icon and the 'Scan or enter QR Code' button -> scanPlumber() -> radio alert (no title; 'Coupon Scan' checked / 'Enter Coupon Code'; buttons 'Cancel' and 'OK'). 'scan' -> scan(): manual_permission == 1 pushes CoupanCode with NO params, else scanQr() -> karigarCoupon -> INVALID / USED ("Coupon Already Used By <first_name> ( <mobile_no> ) on <D-M-Y>") / POINTS NOT EXIST ('No Points Exit This Product') / UNASSIGNED OFFER / else success alert ("<coupon_value> points has been added into your wallet") + getData() again. 'code' -> CoupanCode {mode:'home'}. Cancelled scan = text '' = nothing; a denied/failed scan does nothing (no catch in Ionic). Sales_Boy/Dealer: goOnScanePage() -> same radio alert -> ScanPoint {mode:'home', type:'scan'|'enter_coupon'}.
10. **doRefresh** requests product_catalogue_count TWICE (home.ts:912 and :914), then karigarHome, offerList; refresher.complete() after 1000 ms. loginBannersApp is not re-read.
11. **Offline branches are dead**: dbService.connection is never assigned (only connectionChk). All 'Offline ! Please Connect...' alerts and the 'You Are Offline' toast cannot show; ported behind `(db as any).connection == 'offline'`.
12. **Banner logic** (Plumber, Sales_Boy, Dealer): offers present -> plain slider (no pager, no autoplay), tap = Offers {id}; else login banners in a pager+autoplay(3000) slider; else the bundled banner.png in a pager+autoplay slider. Customer: banners slider, else a plain banner.png image (no slider). Images: upload_url3 + banner / offer_banner.
13. **Share**: socialSharing text built from client.appName and client.playStoreId (Ionic hard-codes Topsan and the Play URL) + ' and use my Code *<referral_code>* to get points back in your wallet' (double space before '..Give it' is Ionic's). Customer Care = tel: link to client.contact.phone (Ionic hard-codes the number).
14. **Push** (initPushNotification, notification(), registrationid(), update_token x2): push is off for Topbath (no push plugin in the production build), so RN calls the no-op wrapper. The 'registration' storage writes (fcmId; user_type and userId are read but never written anywhere) and both update_token calls (home.ts:824 inside notification(), which is never called; home.ts:1079 post_rqst 5 s after a registration event) cannot run. Contract + fixture exist for update_token (post_rqst variant), no driven test.
15. **Dead handlers** (never called from home.html): goOnPointListPage, get_count_ofProducts, goOnOffersListPage, goOnPointeListPage, goOnGiftListPage, viewProfiePic (ViewProfile modal), goOnOpenComplaintAdd, goToNearestDealers, goToFav, add, list, SurveyList, goTodigitalcat, conInt, notification(). The events.subscribe('getCountProducts') handler is dead too (nothing publishes it; it calls the commented-out get_count()). Commented-out template blocks: Digital Catalogue, Nearest Plumbers, Survey, Installation Request box and button for Sales_Boy.
16. **Template details copied**: Customer header toolbar `class="white"` is NOT a colour (default toolbar), the Plumber/Seller toolbar is `color="white"`; `.icon-md-primary` / `.fix-icon` / `.white` have no effect; Plumber boxes 1-3 and Sales_Boy box 1 use the `<span>` count chip (red, even when empty), Customer and Sales_Boy box 2 use `.point h3`; Plumber 'Service Request' shows `plumber`, Sales_Boy/Customer show `complaint`.
